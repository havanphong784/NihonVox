# Learning Preferences Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Let a learner start a local Japanese conversation suited to their chosen level and topic, with a separate short exercise in their chosen writing system.

**Architecture:** Add validated practice preferences and a structured tutor response, then connect them to a new session-start route and the existing shared text/voice turn handler. Keep the active session server-side and persist only the learner’s draft preferences in the browser; keep the legacy session path intact.

**Tech Stack:** Existing FastAPI, Pydantic, httpx, Ollama, faster-whisper, VOICEVOX, vanilla HTML/CSS/JS, pytest and `node:test`. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-20-learning-preferences-design.md`

## Global Constraints

- Level: `N5`, `N4`, `N3`, `N2`, `N1`; writing practice: `hiragana`, `katakana`, `kanji`. Default: `N5`, `hiragana`, `daily`.
- Topic IDs: `daily`, `introductions`, `family`, `school`, `work`, `hobbies`, `restaurant`, `shopping`, `travel`, `weather`, `jlpt`, `free`; labels follow the spec in Vietnamese, including “Nhà hàng/quán cà phê”.
- Level and topic guide the spoken dialogue. Script applies only to the exercise; Japanese dialogue stays natural, with up to two short sentences. Difficulty is guidance, not a guarantee of a JLPT vocabulary classification.
- Vietnamese feedback only when warranted; exercise answer hidden until requested. Voice feedback is based on the transcript, never scored as pronunciation.
- VOICEVOX reads only `reply`. Invalid optional learning fields or VOICEVOX failure must not discard a valid reply. Practice sessions bypass rules; legacy requests retain the existing contract, rules, and one-sentence extraction.
- Keep `japanese-tutor`, `think: false`, all processing local, existing microphone and text input, and no database/framework or long-term progress tracking.
- Work from the existing project without sweeping in other changes. Do not commit or push unless the user asks.

## Review Focus

1. A failed new opener must preserve the visible conversation and its active ID. Cover in Task 2 (browser) and Task 1 (no leaked server slot).
2. An expired or deleted practice session must not silently fall back to generic chat. Cover in Task 1 and give recovery instructions in Task 2.
3. Optional model fields can be malformed or use the wrong script; keep the valid dialogue and never pass exercise text to TTS. Cover in Task 1.
4. Editing a draft select or restarting the page must not silently mutate an existing session. Cover in Task 2.
5. Starting a session while a microphone request is pending or still being finalized must not send the recording to the wrong session. Cover in Task 2.
