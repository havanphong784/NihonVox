# Japanese Conversation Assistant Implementation Plan

> **For agentic workers:** Implement inline using test-driven development and verify before completion. Do not commit or publish; the user requested local files and a running app.

**Goal:** A local Vietnamese web interface for Japanese text conversation and optional VOICEVOX speech.
**Architecture:** Single FastAPI application, shared async HTTP client, per-session bounded in-memory history and locks, UUID WAV files served through a strict filename allowlist. Plain static HTML/CSS/JS, no build step.
**Tech Stack:** Python 3, FastAPI, Uvicorn, httpx, pytest, vanilla JavaScript.
**Spec:** The detailed user request in this conversation.

## Global Constraints
- Project: ~/japanese-voice-assistant; never modify the unrelated initial working repository.
- Ollama: http://127.0.0.1:11434, model japanese-tutor, think=false, stream=false.
- VOICEVOX: http://127.0.0.1:50021, speaker 1, environment-configurable.
- Try requested GET /audio_query; on 405 support the standard POST form.
- Rules bypass Ollama; successful rule turns also enter history.
- Select only the first Japanese sentence, without slicing an unfinished sentence.
- Keep text replies if audio fails; do not synthesize empty replies.
- First browser session is default, stored once in localStorage; deletion uses that saved session ID (initially /sessions/default).
- All content and requests stay local; no frontend frameworks, Docker, external fonts, or microphone.

## Review Focus
- IME composition must not submit a partially composed Japanese phrase.
- Invalid upstream JSON, empty answers, non-Japanese output, invalid WAV and timeouts must be explicit errors.
- Session reset must serialize with an in-flight turn, and different sessions must stay isolated.
- Filenames, symlinks and encoded traversal must not expose arbitrary files.
- Browser storage denial, blocked autoplay and mobile overflow must not break text chat.
